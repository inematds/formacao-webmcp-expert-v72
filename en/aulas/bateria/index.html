Lesson 4 · 18 min

A frozen battery for your tools, and regression when the spec changes

When the code or the spec changes, a site with WebMCP fails silently: detection does not find the API, falls back to the form, and nobody notices. Only a battery catches it. In this lesson you freeze the contract and the cases for the tools, run them in all four modes, and watch the battery catch the old API name.

Start the lesson

In this lesson you will

  1. 1What freezing is and why the hash
  2. 2The four modes: sem, polyfill, native, and MCP
  3. 3The silent regression of the old name
  4. 4What to do when the expected result really changes

02 · Rules for a battery that counts

Inherited from LOOP-R Engenharia (frozen tests) and applied to the tools.

1. Frozen

The expected result does not change just to make the test pass. Did the spec or the rule change? Re-freeze and explain it in the commit.

The hash makes the change visible: nobody edits casos.json without the battery refusing.

2. No model

The cases call the tools directly (executeTool, tools/call), as an agent would.

No model in the loop: the same code gives the same verdict.

3. Mode sem

The round with no API proves that the person books through the form.

It is the first line of the battery, before any agent.

4. Spec changed

New spec, new Chrome or new SDK: run the battery before anything else.

The watcher from lesson 6 tells you when it is time.

Orderwatcher flags it → battery → read what changed → fix or re-freeze with a reason

04 · The silent regression: the old name

navigator.modelContext is the old name (before PR #177, accepted on 05/19/2026). A copy of the page that uses it: the site keeps working, and only the battery notices.

Terminal · page with the old name
cd ~/projetos/formacao-webmcp-expert-v72/kit
E=$(bash scripts/copia.sh a4)
# a regressão: alguém cola um exemplo antigo que usa o nome de antes de 19/05/2026
sed -i 's/const mc = document.modelContext; /const mc = navigator.modelContext; /' $E/pagina/ferramentas.mjs
cd $E && node scripts/bateria.mjs sem nativo | grep -E "FALHA|ok    \[sem\]|BATERIA"; echo "saída: ${PIPESTATUS[0]}"
Example from the repository
ok    [sem] fallback: página sem WebMCP e sem erro de JavaScript · sem
ok    [sem] fallback: a pessoa reserva pelo formulário
FALHA [nativo] contrato: 4 ferramentas com as anotações congeladas · 0 registradas
FALHA [nativo] c1 buscar_oficinas · ferramenta ausente
FALHA [nativo] c2 buscar_oficinas · ferramenta ausente
FALHA [nativo] c3 reservar_vaga · ferramenta ausente
FALHA [nativo] c4 reservar_vaga · ferramenta ausente
FALHA [nativo] c5 reservar_vaga · ferramenta ausente
FALHA [nativo] c6 listar_comentarios · ferramenta ausente
BATERIA: 3/10 ok
saída: 1

The sem mode passes: the person books normally. In nativo, the detection does not find navigator.modelContext in Chromium 156, the page falls back, and the four tools disappear. No JavaScript error: without the battery, nobody would see it.
