Lesson 2 · 18 min

One action, three surfaces: HTML, WebMCP on the page, and MCP on the server

The same booking can arrive through the person on the form, through an agent inside the browser (WebMCP), or through an agent outside it (MCP). If each path has its own copy of the rule, they drift apart. In this lesson the rule lives in a single file, and a script proves that the three surfaces respond the same way and ask for the person.

Start the lesson

In this lesson you will

  1. 1The three surfaces and who arrives through each
  2. 2One rule imported by the page and by the server
  3. 3Three ways to ask for the person before booking
  4. 4The mistake of copying the rule by hand onto the server

Goal: serve the same action through the screen, WebMCP, and MCP with a single rule, and prove that the three respond the same way and ask for the person.

01 · Three doors, one rule

Tap each block.

Click each block in the diagram to see what it does.

In production, the rule and the state live in the backend; in the kit, the rule is the same file and each surface has its own memory.

02 · Where each tool lives

It's not everything on all three. Decide by asking the right question.

1. Screen

Every action the person takes stays in the HTML, accessible and labeled.

It's the fallback for everything: without it, turning off a tool (lesson 7) takes the action offline.

2. WebMCP

When the agent needs what's on the page: an open filter, an item on screen, the person right there to confirm.

It only exists with the API (origin trial or flag); always detect it and have a fallback.

3. MCP

When the agent works outside the browser: a terminal assistant, automation, another service.

Real authorization (OAuth, scope) belongs to the server: course 1, lesson 6.

4. Backend

Rule, state and authorization live in the backend, never only on the page.

The three surfaces are thin doors that call the same rule.

Quick testIf changing the rule means editing two files, it's duplicated.

03 · Download and install the kit

Versions pinned on 10/19/2026: Playwright 1.64.0 (brings Chromium), polyfill 6.0.3, MCP SDK 2.3.1.

Terminal · clone and install
git clone -q https://github.com/inematds/formacao-webmcp-expert-v72 ~/projetos/formacao-webmcp-expert-v72
cd ~/projetos/formacao-webmcp-expert-v72/kit
npm ci --no-audit --no-fund 2>&1 | tail -2
npx playwright install chromium; echo "saída: $?"

The postinstall copies the polyfill to pagina/vendor/, only for the rehearsal. If Chromium is already downloaded, the install prints nothing.

05 · Prove that all three answer the same

Search through the three doors, then three bookings, each one with its own way of asking the person. MCP client in the same process, no port.

Terminal · three surfaces
cd ~/projetos/formacao-webmcp-expert-v72/kit
node scripts/superficies.mjs nativo; echo "saída: $?"
Example from the repository
== Chromium 156.0.8078.4 (Playwright) · modo: nativo · MCP 2026-07-28 (SDK 2.3.1)
buscar_oficinas {"tema":"html","apenasComVaga":true}
  html   → of-101
  webmcp → of-101
  mcp    → of-101
reservar_vaga of-101
  html   → painel Confirmar na página → reservado
  webmcp → consequentialHint + Confirmar na página → reservado

saída: 0

In MCP, the first round of the call returns input_required; the client asks the user and repeats the call (MRTR). The text of the question comes from the server.

  html   → of-101
  webmcp → of-101
  mcp    → of-101,of-102
SUPERFÍCIES: 2/3 iguais na busca · 3/3 reservas esperaram a pessoa
saída: 1

Someone rewrote the filter on the server "so it doesn't depend on the page" and forgot apenasComVaga. MCP now offers of-102, which has no seat left. The proof catches it and exits with 1.

06 · The duplicated-rule rehearsal

On a disposable copy of the kit (scripts/copia.sh): the kit itself does not change.

Terminal · rule copied on the server
cd ~/projetos/formacao-webmcp-expert-v72/kit
E=$(bash scripts/copia.sh a2)
# o erro comum: copiar a regra à mão no servidor (e esquecer o filtro de vaga)
sed -i 's/const oficinas = agenda.buscar(input);/const oficinas = agenda.buscar({}).filter(o => !input.tema || o.tema === input.tema);/' $E/servidor/mcp.mjs
cd $E && node scripts/superficies.mjs nativo | grep -E "→ of|SUPERF"; echo "saída: ${PIPESTATUS[0]}"
