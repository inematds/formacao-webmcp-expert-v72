Lesson 3 · 15 min

Observability: logging calls, errors, and cancellations

In production, "the agent couldn't book" only gets solved with a log. Every tool call, through any door, leaves a line: surface, tool, result, and time. No personal data. In this lesson you trigger the possible outcomes and read what each one leaves in the log.

Start the lesson

In this lesson you will

  1. 1What a log line needs to have
  2. 2The observado() wrapper on the three doors
  3. 3Error, refusal, cancellation, and the MRTR request
  4. 4Why the log keeps the field name and not the value

Goal: log every call across the three surfaces with result and time, with no personal data, and read the possible outcomes in the log.

01 · From the request to the line in the log

The log sits at the boundary, not inside the rule. Click each step.

Click each block in the diagram to see what it does.

02 · The outcomes that matter

Each one calls for a different action from whoever runs the site.

1. erro

Input that the rule does not accept: invalid topic, workshop with no spots left.

Many errors on the same tool = a confusing description or schema for the agent.

Kitmotivo: tema inválido: cobol

2. recusado

The confirmation worked. It is not a site failure.

Many refusals = the agent is proposing the wrong thing; look at what it asked for.

3. cancelado

The agent gave up (or the person left) before the response: executeTool was canceled by the signal.

Measured in the kit: the cancellation reaches execute as AbortError and the booking does not happen.

4. pediu-pessoa

In MCP 2026-07-28, the first round of an action with confirmation returns input_required.

That is why a booking through MCP leaves two lines: the request and the outcome.

03 · The wrapper

The same file serves the page and the server. On the page, in production, the line would go to your backend (sendBeacon, for example); in the kit it stays in memory.

File · kit/pagina/registro.mjs
// registro.mjs — observabilidade nas fronteiras: uma linha por chamada de ferramenta, em qualquer superfície.
// Roda no navegador (página) e no Node (servidor MCP). Não guarda dado pessoal: só o NOME dos campos de entrada.
// Resultado: ok | erro (regra recusou) | recusado (a pessoa disse não) | cancelado (AbortSignal) | excecao
//            | pediu-pessoa (MCP: a 1ª volta do MRTR devolve input_required e o cliente pergunta ao usuário).

const linhas = [];
let destino = null;   // função que recebe cada linha (no servidor: grava JSONL; na página: sendBeacon em produção)

export function aoRegistrar(fn) { destino = fn; }
export function linhasRegistradas() { return linhas.map(l => ({ ...l })); }

export function classificar(r) {
  if (r && typeof r === 'object') {
    if (r.resultType === 'input_required') return 'pediu-pessoa';
    if ('erro' in r) return 'erro';
    if (r.reservado === false) return 'recusado';
  }
  return 'ok';
}

export function anotar(linha) {
  const l = { t: new Date().toISOString(), ...linha };
  linhas.push(l);
  globalThis.__registro = linhas;    // os testes leem daqui
  destino?.(l);
  return l;
}

// Embrulha o execute de uma ferramenta: mede o tempo e anota o resultado, sem mudar o que ela devolve.
export function observado(superficie, ferramenta, fn) {
  return async (input = {}, opcoes) => {
    const inicio = performance.now();
    const base = { superficie, ferramenta, campos: Object.keys(input).sort() };
    try {
      const r = await fn(input, opcoes);
      anotar({ ...base, resultado: classificar(r), ms: Math.round(performance.now() - inicio), ...(r?.erro ? { motivo: r.erro } : {}) });
      return r;
    } catch (e) {
      anotar({ ...base, resultado: e.name === 'AbortError' ? 'cancelado' : 'excecao', ms: Math.round(performance.now() - inicio), motivo: e.name });
      throw e;
    }
  };
}

The script searches, gets the topic wrong, refuses, cancels, and books through MCP with a refusal. It writes logs/chamadas.jsonl.

The last line is a real line from the file: the fields id and nome show up by name, never by value. The milliseconds vary on each run.

REGISTRO: 8 chamadas · ok 3 · erro 1 · recusado 2 · cancelado 1 · pediu-pessoa 1 · dado pessoal no registro: SIM
saída: 1

Someone swapped campos for entrada: input "to debug". People's names ended up in the log, and the script exits with 1. A log with personal data becomes a liability (LGPD): log what helps you operate, not what identifies someone.

15 min
