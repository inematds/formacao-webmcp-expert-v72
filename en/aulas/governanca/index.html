Lesson 7 · 16 min

Production and governance: who approves a new tool, versioning, shutting it off fast

A tool for an agent is an action on your site performed by someone else. It needs an owner, an approval date, an autonomy level, and a way to go offline in minutes without breaking the form. In this lesson the approved catalog becomes a file that the page and the server read, a script checks it, and a state shuts a tool off.

Start the lesson

In this lesson you will

  1. 1The approved catalog (governanca.json)
  2. 2Autonomy levels from 0 to 3
  3. 3The script that checks code × catalog
  4. 4Shutting off a tool while keeping the form

Goal: put each tool in a catalog with an owner, a date, and an autonomy level, and shut one off without a code deploy and without breaking the form.

02 · Autonomy levels

From INEMA's agent constitution model, applied to the site's tools.

1. 3

Executes and logs. For what only reads: search, list, view.

In the kit: buscar_oficinas, listar_comentarios, minhas_reservas.

2. 2

Executes and notifies the person in charge.

For small, reversible effects, with a notice to whoever looks after it.

3. 1

Prepares and waits for the person to approve: the page's Confirmar, the MCP's MRTR.

In the kit: reservar_vaga. Every action with consequences stays here or below.

4. 0

Hands off to a person. It cannot be active.

E.g.: canceling someone's enrollment, refunding a payment.

Script ruleconsequence and level above 1 = problem; level 0 active = problem

03 · The approved catalog

The page reads it with fetch (cache: no-store); the server reads it from disk on every request. Without the file, nothing goes out: it fails closed.

04 · Check code × catalog

governanca.mjs reads the tools the code knows about (page and server) and compares them with the catalog.

Terminal · the kit's catalog and a bad catalog
cd ~/projetos/formacao-webmcp-expert-v72/kit
node scripts/governanca.mjs; echo "saída: $?"
node scripts/governanca.mjs governanca/ruim.json | grep -E "PROBLEMA|GOVERN"; echo "saída: ${PIPESTATUS[0]}"
Example from the repository
catálogo 2026-10-19.1 · 4 ferramentas (4 ativas) · código: 4 na página, 2 no servidor
GOVERNANÇA: 0 problema(s)
saída: 0
PROBLEMA reservar_vaga: tem consequência e está no nível 3 (máximo 1: propõe e espera a pessoa)
PROBLEMA minhas_reservas: está no código (webmcp) mas não no catálogo aprovado
PROBLEMA listar_comentarios: sem data de aprovação (AAAA-MM-DD)
GOVERNANÇA: 3 problema(s)
saída: 1

The bad catalog puts reservar_vaga at level 3 (it would act alone), forgets minhas_reservas, and doesn't date the approval of listar_comentarios.

05 · Switch off fast

On a copy of the page, the state of reservar_vaga becomes desligada. No code changes.

Terminal · switch off reservar_vaga
cd ~/projetos/formacao-webmcp-expert-v72/kit
node scripts/desligar.mjs reservar_vaga nativo; echo "saída: $?"
Example from the repository
== Chromium 156.0.8078.4 (Playwright) · modo: nativo
antes:  WebMCP 4 ferramentas · MCP 2 ferramentas
desligada: reservar_vaga (estado "desligada" no governanca.json, nenhum código mudou)
depois: WebMCP 3 ferramentas · MCP 1 ferramentas
formulário: a pessoa reservou of-301 normalmente
DESLIGAR: ok · reservar_vaga fora do WebMCP e do MCP, formulário funcionando
saída: 0

In production, the same applies when you publish the new governanca.json: the page reads it without cache on the next load, the server on the next call. An agent with the page already open still sees the tool until it reloads.

06 · Practice

Check, switch off, and write your site's catalog.

E1 · Catalog in order

3 min

Run the catalog check.

Done when: node scripts/governanca.mjs; echo "saída: $?" → GOVERNANÇA: 0 problema(s) and saída: 0; the bad one → GOVERNANÇA: 3 problema(s) and saída: 1.

E2 · Switch off without a deploy

5 min

Run the drill that switches off reservar_vaga.

Done when: node scripts/desligar.mjs reservar_vaga nativo; echo "saída: $?" → depois: WebMCP 3 ferramentas · MCP 1 ferramentas, DESLIGAR: ok and saída: 0.

E3 · Your site's catalog

20 min

Write the governanca.json for your site's tools: owner, date, level, and surfaces. Agree with your team on who can change the state to desligada and how fast.

Done when: In your copy of the kit with your tools, node scripts/governanca.mjs; echo "saída: $?" → 0 problema(s) and saída: 0.

08 · In three sentences

CatalogEvery exposed tool has an owner, a date, a level, and surfaces in a single file.
LevelAnything with consequences stays at 1 (proposes and waits) or 0 (does not touch).
Turn offThe desligada state removes the tool from both doors without a deploy; the form stays.
